## Must-Fix Before 1.0

### 1. Named Capture Groups Should Return Dictionaries (#97)

**Current Behavior:**
```parsley
"John Smith" ~ /(?P<first>\w+)\s+(?P<last>\w+)/
// Returns: ["John Smith", "John", "Smith"]
```

**Expected Behavior:**
```parsley
"John Smith" ~ /(?P<first>\w+)\s+(?P<last>\w+)/
// Should return: {first: "John", last: "Smith"} (or include full match)
```

**Impact:** High. Users explicitly name captures for a reason—ignoring the names is surprising and forces awkward array indexing instead of semantic field access.

**Effort:** Small (~1-2 hours). Modify regex match result construction in evaluator.

**Location:** `pkg/parsley/evaluator/eval_regex.go`

---

### 2. Custom Message for `failIfInvalid(msg?)` (#90)

**Current Behavior:**
```parsley
record.failIfInvalid()
// Always uses: "Validation failed"
```

**Expected Behavior:**
```parsley
record.failIfInvalid("Invalid user data")
// Uses custom message: "Invalid user data"
```

**Impact:** Medium. Hardcoded message limits usefulness of validation errors in user-facing applications.

**Effort:** Small (~30 minutes). Add optional string parameter to `recordFailIfInvalid()`.

**Location:** `pkg/parsley/evaluator/methods_record.go:253-280`

### Test Infrastructure Notes

1. **Integration Test Pattern**: Parsley uses integration tests (`pkg/parsley/tests/`) that exercise the full parse→eval pipeline. This is more valuable than unit tests for a language implementation.

2. **Coverage Measurement**: Run with `-coverpkg` to get accurate cross-package coverage:
   ```bash
   go test -coverprofile=cov.out -coverpkg=./pkg/parsley/evaluator ./pkg/parsley/...
   ```

3. **153 Test Files**: The test suite is comprehensive with ~58,000 lines of test code covering:
   - All data types (arrays, dicts, strings, numbers, units, money, datetime, duration)
   - All operators and control flow
   - All stdlib modules
   - File I/O, imports, exports
   - Records, schemas, validation
   - Tags and HTML generation

2. **#94/#95 clarification**: `pars --check` exists and works. #94 refers to multiple `-e` flags (different feature). #95 specifically refers to stdin support (`pars --check -`), which is not implemented.

3. **Deprecations moved to 1.0**: All deprecation warnings should be added before 1.0, not after. Updated action items accordingly.

4. **`@std/dev` is Basil-only**: All functionality requires `env.DevLog` (set by Basil server). In CLI mode, all calls are no-ops. Added note recommending rename to `@basil/dev`.

5. **`format(array, style)` is redundant**: The global function does exactly the same thing as `array.format(style)` method. Added to deprecation list.
