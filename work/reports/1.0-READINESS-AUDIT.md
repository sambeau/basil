## Executive Summary

This audit identifies deprecated code, significant TODOs, and items requiring attention before the Parsley 1.0 release. Two items are recommended as **must-fix** before 1.0; the remainder can be deferred.

---

## Must-Fix Before 1.0

### 1. Named Capture Groups Should Return Dictionaries (#97)

**Current Behavior:**
```parsley
"John Smith" ~ /(?P<first>\w+)\s+(?P<last>\w+)/
// Returns: ["John Smith", "John", "Smith"]
```

**Expected Behavior:**
```parsley
"John Smith" ~ /(?P<first>\w+)\s+(?P<last>\w+)/
// Should return: {first: "John", last: "Smith"} (or include full match)
```

**Impact:** High. Users explicitly name captures for a reason—ignoring the names is surprising and forces awkward array indexing instead of semantic field access.

**Effort:** Small (~1-2 hours). Modify regex match result construction in evaluator.

**Location:** `pkg/parsley/evaluator/eval_regex.go`

---

### 2. Custom Message for `failIfInvalid(msg?)` (#90)

**Current Behavior:**
```parsley
record.failIfInvalid()
// Always uses: "Validation failed"
```

**Expected Behavior:**
```parsley
record.failIfInvalid("Invalid user data")
// Uses custom message: "Invalid user data"
```

**Impact:** Medium. Hardcoded message limits usefulness of validation errors in user-facing applications.

**Effort:** Small (~30 minutes). Add optional string parameter to `recordFailIfInvalid()`.

**Location:** `pkg/parsley/evaluator/methods_record.go:253-280`

## Deprecated Code

### AST Fields (pkg/parsley/ast/ast.go)

| Field | Type | Replacement | Notes |
|-------|------|-------------|-------|
| `TagLiteral.Spreads` | `[]*SpreadExpr` | Use `Attributes` | Legacy spread handling |
| `TagPairExpression.Props` | `string` | Use `Attributes` | Raw props string |
| `TagPairExpression.Spreads` | `[]*SpreadExpr` | Use `Attributes` | Legacy spread handling |
| `QueryModifier.Fields` | `[]string` | Use `OrderFields` | For order clauses only |
| `QueryModifier.Direction` | `string` | Use `OrderFields` | Per-field direction now |

**Recommendation:** These can remain for backward compatibility. Consider removal in 2.0.

### Deprecated Builtins & Modules

| Item | Replacement | Notes |
|------|-------------|-------|
| `now()` function | `@now` literal | Datetime literal syntax preferred |
| `@std/table` module | `@table` literal | Literal syntax is cleaner |
| `<Label>`, `<Error>` components | `<label>`, `<error>` | Lowercase preferred |
| `<Meta @field>` component | `<val @field @key="help"/>` | More explicit syntax |

**Recommendation:** Add deprecation warnings in 1.x, remove in 2.0.
