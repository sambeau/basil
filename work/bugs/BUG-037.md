# BUG-037: the first publish from a graduated project failed opaquely

## Summary
A project that graduated to a server (`basil --init` locally, then a server `basil
--init --server`, then `git remote add origin` + push) could not make its FIRST publish
through `basil publish`. Server init seeds the release branch with its own starter
commit, so the local project's history and the server's are unrelated. Two things
followed from that:

1. **`basil publish` failed opaquely.** It read the server's release branch and tip with
   `git ls-remote --symref origin HEAD` (FEAT-157), then computed a `<serverTip>..HEAD`
   range to publish. The server's starter commit is not in the local repository at all,
   so `git rev-list <serverTip>..HEAD` exited 128 ("bad revision"), surfacing as a
   generic "cannot determine what would be published".

2. **Git refuses the non-fast-forward without `--force`.** Even past the range problem,
   moving the release branch onto an unrelated commit is a non-fast-forward.

The only documented path was raw `git push --force origin main:live`. The *server* side
was already correct and safe: the hub (`cmd/basil/fromhook.go`,
`deploy.OnlyInitDeployed`) accepts exactly one starter-overwrite non-fast-forward while
the deploy record shows only the init release, under the deploy lock, and refuses it
otherwise (BUG-035 companion, FEAT-156). This bug was purely the *client* ergonomics.

## Reproduction
`TestGitE2E_FirstPublishViaBasilPublish` (`server/git_e2e_test.go`) is the bug written
down against a real hub: a local-init project, a server-init hub, `git remote add`, then
`basil publish --yes` (not raw git). Before the fix, publish exits non-zero on the
`rev-list` 128; after it, the forced push lands, the release branch moves onto the local
head, and the server serves the local project's page.

## Fix
Client-side only; the hub's refusal logic is untouched.

1. **Detect the state.** After `ls-remote --symref` gives the release branch and tip,
   `unrelatedHistories` (`cmd/basil/publish.go`) fetches the tip and runs `git
   merge-base <serverTip> HEAD`. The fetch is what makes the probe authoritative: a
   graduated project has never seen the starter commit, but neither has a clone that has
   merely fallen behind seen the newer tip, and `git merge-base` cannot tell "no common
   ancestor" from "an object I have never seen" — both exit non-zero. With the tip landed
   locally, merge-base is decisive: exit 0 is a shared ancestor (ordinary), non-zero is
   genuinely unrelated. A fetch that cannot land the object leaves the question open, and
   an open question is never a force.

2. **Offer the forced push.** `firstPublish` mirrors publish's voice — a plan, a
   confirmation (`--yes` skips, `--dry-run` previews and does nothing), the push streamed
   so the server's `remote:` lines appear — but the push is `git push --force origin
   HEAD:refs/heads/<branch>`, using the branch the server advertises, never a hardcoded
   `live`. After it succeeds, `configureReleasePush` sets `remote.origin.push` so every
   later publish is an ordinary `basil publish`.

3. **Never force ordinary divergence.** The offer is reached only when histories are
   unrelated AND origin answered. A shared-history clone that is behind or has diverged
   falls through to the existing path, which refuses the non-fast-forward and points at
   fetch-and-rebase. The server remains the backstop — it honours the force only while
   init-only — but the client does not offer it for anything else.

The manual `git push --force origin HEAD:<branch>` still works for anyone who prefers it.

Covered by `TestPublish_FirstPublishFromGraduatedProject`,
`TestPublish_FirstPublishDryRunPushesNothing`, `TestPublish_FirstPublishPromptAborts`,
`TestPublish_OrdinaryDivergenceIsNotOfferedAForce`,
`TestPublish_DivergentLocalCommitIsNotUnrelated`,
`TestUnrelatedHistories_ClassifiesUnrelatedRootsAsTrue` (`cmd/basil/publish_test.go`),
and the end-to-end `TestGitE2E_FirstPublishViaBasilPublish` and
`TestGitE2E_FirstPublishDryRunLeavesStarterServing` (`server/git_e2e_test.go`).
