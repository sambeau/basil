# BUG-024: array.join() does not skip null values, producing spurious separators

## Summary

`array.join(separator)` converts null elements to empty strings but still inserts the separator around them, producing double separators, trailing separators, or leading separators depending on where the nulls appear.

## Reproduction

```bash
pars -e '["field", null, "extra"].join(" ")'
# Actual:   "field  extra"   (double space)
# Expected: "field extra"

pars -e '["field", null].join(" ")'
# Actual:   "field "         (trailing space)
# Expected: "field"

pars -e '["a", null, null, "b"].join(",")'
# Actual:   "a,,,b"          (double comma)
# Expected: "a,b"

pars -e '["a", "", "b"].join(",")'
# Actual:   "a,,b"           (empty string also gets separators)
# Expected: "a,b"            (debatable — see Design Decision below)
```

## Root Cause

In `pkg/parsley/evaluator/methods_array.go`, `arrayJoin` (line ~277) converts every element to a string via `objectToTemplateString()` and collects them into a `[]string` slice. Nulls become `""` but still occupy a slot. `strings.Join()` then places a separator between every slot, including the empty ones.

```go
items := make([]string, len(arr.Elements))
for i, elem := range arr.Elements {
    items[i] = objectToTemplateString(elem)
}
return &String{Value: strings.Join(items, separator)}
```

## Fix

Skip null elements when building the items slice:

```go
items := make([]string, 0, len(arr.Elements))
for _, elem := range arr.Elements {
    if _, ok := elem.(*Null); ok {
        continue
    }
    items = append(items, objectToTemplateString(elem))
}
return &String{Value: strings.Join(items, separator)}
```

## Design Decision: Should empty strings also be skipped?

Null should definitely be skipped — null represents "no value" and should not contribute a separator. Empty strings (`""`) are debatable:

- **Skip both null and `""`**: Makes `("field" ++ class).join(" ")` work perfectly for class merging — if `class` is null OR `""`, no trailing space. This is the more useful behaviour.
- **Skip only null**: `""` is a real string value that the user explicitly placed in the array. Skipping it silently could be surprising.

**Recommendation:** Skip both null and empty string. The rationale: `join()` is a string-assembly operation, and neither null nor `""` contribute meaningful content. Users who want an empty slot to produce separators can use a space `" "` instead. This matches the behaviour of similar functions in Ruby (`compact.join`), Python (list comprehension + join), and JavaScript (`.filter(Boolean).join()`).

## Impact

- **Prelude class merging** — All 12 prelude components use a verbose `if/else` pattern for class merging because `join()` can't be trusted with nulls. With this fix, the pattern simplifies from:
  ```parsley
  class={"field" + if (class) { " " + class } else { "" }}
  ```
  to:
  ```parsley
  class={("field" ++ class).join(" ")}
  ```
- **Any user code** that joins arrays containing optional values (e.g., building URLs, assembling paths, constructing sentences) is affected.

## Verification

After fix:

```bash
pars -e '["field", null, "extra"].join(" ")'     # "field extra"
pars -e '["field", null].join(" ")'              # "field"
pars -e '["a", null, null, "b"].join(",")'       # "a,b"
pars -e '[null].join(",")'                       # ""
pars -e '["a", "b", "c"].join(",")'              # "a,b,c" (unchanged)

# If empty strings are also skipped:
pars -e '["a", "", "b"].join(",")'               # "a,b"

go test ./pkg/parsley/...
```

## Implementation Notes

**Fixed in commit on fix/BUG-024-array-join-skip-nulls branch**

The fix was implemented exactly as described in the "Fix" section above. Both null values and empty strings are skipped when building the items slice before joining.

### Changes Made
1. `pkg/parsley/evaluator/methods_array.go`: Modified `arrayJoin` to skip null and empty string elements
2. `pkg/parsley/tests/string_conv_test.go`: Added 6 regression tests covering:
   - Single null skip
   - Multiple consecutive nulls
   - Trailing null
   - Empty string skip
   - All-null array
   - Class merge pattern (primary use case)

### Verification
All tests pass including the new regression tests. Manual verification confirms:
```bash
pars -e '["field", null, "extra"].join(" ")'     # "field extra" ✓
pars -e '["field", null].join(" ")'              # "field" ✓
pars -e '["a", null, null, "b"].join(",")'       # "a,b" ✓
pars -e '[null].join(",")'                       # "" ✓
pars -e '["a", "b", "c"].join(",")'              # "a,b,c" ✓ (unchanged)
pars -e '["a", "", "b"].join(",")'               # "a,b" ✓
```
