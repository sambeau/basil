# BUG-034: containment checks mis-compare when a path cannot be resolved

## Summary
`checkRepoOutsideServedRoots` ([`server/server.go`](../../server/server.go)) refuses to
start the Git endpoint when the bare repository sits inside anything the server serves
files from — a repository under a served root would hand every version of every file to
anyone with a browser. It resolved both sides with `filepath.EvalSymlinks` and, when
that failed, fell back to the **unresolved** absolute path.

`EvalSymlinks` fails outright on a path that does not exist. One side of the comparison
could therefore be fully resolved while the other was not, and on macOS — where `/var`
is a symlink to `/private/var` — the two then sit in different namespaces:
`filepath.Rel("/private/var/…", "/var/…/site.git")` returns `../../..`, `pathContains`
reports false, and a repository directly inside a served root is judged outside it.

## Scope of the exposure
Narrower than it first looks, and worth stating plainly. `initGit` stats the repository
and returns early when it is absent, so on the ordinary startup path the repository
exists; and for containment to be *true* the served root must be an ancestor of the
repository, so it exists too. Both sides resolve, and the check holds. The defect is
that its correctness rests entirely on that stat ordering in the caller rather than on
the helper itself — remove or reorder the stat, add a call site, or hit a path
`EvalSymlinks` cannot resolve for another reason, and the check silently passes
something it exists to refuse.

`basil doctor`'s `checkRepository` ([`cmd/basil/deploy.go`](../../cmd/basil/deploy.go))
carried a second copy of the same helper with the flaw in the other direction: there the
repository is stat'd but the *served roots* are not, so a root the operator has not
created yet resolved in a different namespace and could never match.

## Reproduction

```bash
go test ./server/ -run TestCheckRepoOutsideServedRoots
```

On macOS this failed at the `static[].root` case: `Static[0].Root` is a `t.TempDir()`
(exists, resolves to `/private/var/…`) while `root/site.git` does not exist (stays
`/var/…`), so a repository directly inside the served static root was accepted.

## Fix
Path resolution now walks up to the deepest ancestor that *does* exist, resolves that
through symlinks, and re-joins the components below it, so a path that has not been
created yet lands in the same namespace as one that has. The resolver is shared rather
than duplicated — `config.RealPath` in
[`server/config/paths.go`](../../server/config/paths.go) — and `server.resolveRealPath`
and `main.resolvedPath` are gone.

Covered by `TestCheckRepoOutsideServedRoots` (`server/config/paths_test.go`, where BUG-035 moved it with the function it tests) and by
`TestRealPathResolvesNonExistentPaths` (`server/config/paths_test.go`), which pins the
namespace-agreement property the containment checks rest on.
