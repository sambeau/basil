# BUG-027: `~` ignored the `g` flag

## Summary
The manual (regex.md, "Extract All Matches") documents that `text ~ /pattern/g`
returns **all** matches, and `.replace()` already honours `g`. But
`evalMatchExpression` always used `FindStringSubmatch` and never consulted the
flags, so `~` returned only the first match regardless of `g`.

## Observed
```parsley
"Call 555-1234 or 555-5678" ~ /\d{3}-\d{4}/g
// was:  ["555-1234"]
// docs: all matches
```

## Fix
`evalMatchExpression` (pkg/parsley/evaluator/eval_regex.go) now branches on the
`g` flag and uses `FindAllStringSubmatch`:

- plain pattern → array of full-match strings: `["555-1234", "555-5678"]`
- capture groups → one `[full, group1, …]` array per match
- named groups → one match dictionary per match
- no matches → `null` (unchanged)
- without `g` → behaviour unchanged (first match)

## Test Coverage
`TestRegexMatchGlobal` in pkg/parsley/tests/regex_test.go.

## Related
Found while proofreading the manual against the implementation. The same pass
found doc-side errors in regex.md (a `.split(/re/)` example — `split` is
string-only — and a wrong expected output for a `replace(/…/g)` example).
