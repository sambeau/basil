# BUG-049: basil.public_dir was never the public dir

## Summary

In site mode — the layout every `basil --init` project uses —
`asset(@./public/images/logo.png)` returned `/public/images/logo.png`. That
URL does not 404: the site catch-all serves it as HTML, so the page renders, the
image quietly doesn't, and nothing points at asset(). In routes mode without a
per-route `public_dir`, asset() returned its argument unchanged.

Found while writing the routing docs' "how do I reference an image?" paragraph:
the documented example was tested at the HTTP surface before being published,
and did not do what the docs said. The docs were corrected first (to recommend
the plain `/images/logo.png` URL, which is right anyway); this fixes the
builtin underneath.

## Cause

`route.PublicDir` is overloaded, and one consumer didn't know.

In site mode, `site.go` builds its synthesized routes with
`PublicDir: handlerRoot` — the *project root*, not the public directory — so
that the RootPath logic in `handler.go` anchors `@~/` and relative paths there
(BUG-011). That works because the RootPath logic knows the convention: "the
handler script living inside route.PublicDir means site mode".

`buildBasilContext` did not know the convention. It exported `route.PublicDir`
as `basil.public_dir` verbatim, and `pathToWebURL` (the function behind
asset()) then treated the project root as the public directory:
`<root>/public/images/logo.png` is under `<root>`, so it stripped `<root>` and
produced `/public/images/logo.png`. The arithmetic ran perfectly on the wrong
operand.

The routes-mode half is the same wiring with the opposite symptom: a route
without its own `public_dir` has an empty `route.PublicDir` (config only copies
the global one onto the `/` route), so `basil.public_dir` was empty and
asset()'s documented fallback — return the path unchanged — fired on every
call.

## Fix

`contextPublicDir()` (server/handler.go) computes what `basil.public_dir`
should name, and both `buildBasilContext` call sites (page and API handlers)
use it:

- **Site mode** — detected the same way the RootPath logic detects it (the
  handler script lives inside `route.PublicDir`) — exports the config's
  `public_dir`.
- **Routes mode** with a per-route `public_dir` exports that; without one it
  falls back to the config's global `public_dir` instead of empty.

`route.PublicDir` itself is untouched: the RootPath convention, the static
fallback wiring, and `@~/` resolution all keep working from the same field.
Only the value exported to Parsley changes.

asset()'s documented contract — strip the prefix if the path is under
`public_dir`, return the path unchanged otherwise — is deliberately unchanged.
The passthrough is pinned by existing tests
(`pkg/parsley/tests/asset_files_test.go`) and documented in three places;
whether it should instead be an error (a typo'd path now comes back as a
broken relative URL rather than a loud failure) is a design question, left
open rather than smuggled into a bug fix.

Also noted on the way: automatic rewriting of path literals in tag attributes
(`<img src={@./public/logo.png}/>` → `/logo.png`) does not exist and never did
— `pathToWebURL`'s only caller is asset(). Several doc pages claimed it; they
were corrected to describe web-root serving on 2026-08-27, before this fix.

## Verification

- `TestAssetURLSiteMode` (server/asset_url_test.go) — a site-mode server built
  over a temp project; asserts the handler's output contains
  `/images/logo.png`, does **not** contain `/public/images/logo.png`, and that
  a GET of the returned URL through the same mux serves the file's bytes.
  Fails on the old code with `asset() kept the public prefix (BUG-049):
  "/public/images/logo.png"`.
- `TestAssetURLRouteModeGlobalPublicDir` — the routes-mode half, with the `/`
  route carrying the global public_dir the way `ResolvePaths` arranges it.
  Fails on the old code with the passthrough (`"./public/images/logo.png"`).
- Both confirmed failing with the fix stashed, passing with it restored.
- Verified in the running app: `basil --dev` on a real `--init` project,
  `<img src={asset(@./public/images/logo.png)}/>` renders
  `src="/images/logo.png"` and that URL returns the image with
  `Content-Type: image/png`.
- Existing asset()/public_dir suites (`asset_files_test.go`,
  `public_dir_test.go`) pass unchanged — the contract they pin is untouched.
- `go build ./...`, `go vet ./...`, `go test ./...`.
