# BUG-023: Phantom operators and incorrect builtin metadata in introspect.go

## Summary

`pkg/parsley/evaluator/introspect.go` contains metadata for 3 operators that don't exist in the parser, 1 missing builtin entry, and 2 incorrect builtin descriptions. Since `pars describe` is the designated source of truth for AI agents and documentation generation, these errors propagate into generated docs, the CHEATSHEET verification workflow, and any tooling that consumes `pars describe all --json`.

## Impact

- **`pars describe operators`** reports `**`, `|>`, and `?:` as real operators — they are not
- **`pars describe builtins`** omits `unit()` — it exists and works
- **`pars describe match`** says it's a regex matcher with 3 params — it's a path matcher with 2
- **`pars describe format`** says it formats strings with placeholders — it formats arrays/durations
- AI agents (Copilot, Claude) that follow the copilot instructions to trust `pars describe` will generate broken code using these phantom features
- `pars reference --format markdown` generates an API reference containing phantom operators

## Findings

### 1. Phantom Operators (OperatorMetadata)

| Operator | Claimed | Actual |
|----------|---------|--------|
| `**` | Exponentiation (`2 ** 3`) | ❌ Parse error: `unexpected '*'` |
| `\|>` | Pipe (`data \|> transform`) | ❌ Parse error: `unexpected '>'` |
| `?:` | Ternary (`x > 0 ? "pos" : "neg"`) | ❌ Parse error: `unexpected '?'`. Parsley uses `if/else` expressions |

**Location:** `pkg/parsley/evaluator/introspect.go` lines 312, 340, 348

**Verification:**
```bash
pars -e '2 ** 3'                    # Parser error
pars -e '5 |> toFloat'              # Parser error
pars -e 'true ? "yes" : "no"'      # Parser error
```

### 2. Missing Builtin: `unit`

The `unit()` builtin works but has no entry in `BuiltinMetadata`:

```bash
pars -e 'unit(5, "km")'            # Returns #5km
pars describe unit                  # Shows type info (from registry), not builtin info
```

**Location:** Builtin registered in `evaluator.go` ~L3920 but absent from `BuiltinMetadata` map in `introspect.go`.

### 3. Wrong Description: `match()`

| Field | Current (wrong) | Correct |
|-------|-----------------|---------|
| Description | "Match string against pattern" | "Match path/URL against pattern with named captures" |
| Category | `regex` | `path` (or `pattern`) |
| Arity | `2-3` | `2` |
| Params | `string, pattern, flags?` | `path, pattern` |

**Verification:**
```bash
pars -e 'match("/users/42", "/users/:id")'      # {id: "42"} — path matcher
pars -e 'match("hello", "hel.*")'                # null — NOT regex
pars -e 'match("/x", "/x", "extra")'             # Error: got=3, want=2
```

### 4. Wrong Description: `format()`

| Field | Current (wrong) | Correct |
|-------|-----------------|---------|
| Description | "Format string with placeholders" | "Format array as list or duration as relative time" |
| Params | `template, values...` | `value, style?, locale?` |

**Verification:**
```bash
pars -e 'format("hello %s", "world")'   # Error: must be duration or array
pars -e 'format([1,2,3], "and")'         # "1, 2, and 3"
```

## Fix

### File: `pkg/parsley/evaluator/introspect.go`

#### Remove phantom operators (lines ~312, ~340, ~348):

Delete these entries from `OperatorMetadata`:

```go
// DELETE:
"**": {Symbol: "**", Name: "Exponentiation", Description: "Raise to power", Category: "arithmetic", Example: "2 ** 3"},
"|>": {Symbol: "|>", Name: "Pipe", Description: "Pass left value as first argument to right function", Category: "pipe", Example: "data |> transform"},
"?:": {Symbol: "?:", Name: "Ternary", Description: "Conditional expression: condition ? then : else", Category: "control", Example: "x > 0 ? \"pos\" : \"neg\""},
```

#### Add missing `unit` builtin:

```go
// === Units ===
"unit": {Name: "unit", Arity: "2", Description: "Create unit value from number and suffix", Params: []string{"value", "suffix"}, Category: "conversion"},
```

#### Fix `match()` entry:

```go
"match": {Name: "match", Arity: "2", Description: "Match path/URL against pattern with named captures (:name, *name)", Params: []string{"path", "pattern"}, Category: "path"},
```

#### Fix `format()` entry:

```go
"format": {Name: "format", Arity: "1-3", Description: "Format array as list (and/or/unit) or duration as relative time", Params: []string{"value", "style?", "locale?"}, Category: "format"},
```

## Verification

After fix, confirm:

```bash
# Phantom operators gone
pars describe operators | grep -c "Pipe\|Exponentiation\|Ternary"   # Should be 0

# unit listed
pars describe unit                      # Should show builtin info

# match description correct
pars describe match                     # Should say "path/URL" not "regex"

# format description correct
pars describe format                    # Should say "array" not "string with placeholders"

# All tests pass
go test ./pkg/parsley/...
```

## Test Coverage

The existing `help_test.go` tests validate that `pars describe operators` returns results, but they don't assert the absence of specific operators. Add:

1. Test that `OperatorMetadata` only contains operators that actually parse
2. Test that every entry in `BuiltinMetadata` matches the actual builtin's arity (call with wrong arg count, verify error says the expected arity)
