# FEAT-129: Parsley Standard Library v1.0 Cleanup

## Summary

Clean up the Parsley standard library for v1.0 release by removing redundant modules/functions, establishing clear namespace boundaries between `@std/` (pure Parsley) and `@basil/` (server-specific), adding missing functionality (hash module, string methods, ID validators), and documenting migration paths.

## User Story

As a Parsley developer, I want a clean, focused standard library with clear namespace boundaries so that I can understand what functionality is available and use consistent patterns for validation, hashing, and string manipulation.

## Acceptance Criteria

### Phase 1: Deprecations
- [x] `@std/schema` emits deprecation warning (DEP-002) with migration guide to `@schema` DSL syntax

### Phase 2: `@std/valid` Refactor
- [x] Remove 27 redundant functions (type checks, constraints, format validators covered by schema)
- [x] Keep: `uuid`, `creditCard`, `luhn`, `postalCode`
- [x] Add: `ulid`, `nanoid(str, len?)`, `cuid`
- [x] All ID types generated by `@std/id` can be validated by `@std/valid`

### Phase 3: New `@std/hash` Module
- [x] `hash.md5(str)` returns hex-encoded MD5 hash

- [x] `hash.sha256(str)` returns hex-encoded SHA256 hash

## Design Decisions

- **Namespace separation**: `@std/` contains pure Parsley functionality that works without Basil; `@basil/` contains server-specific functionality. This allows Parsley to remain a general-purpose language.

- **Validators stay together**: ID validators (`ulid`, `nanoid`, `cuid`) live in `@std/valid` rather than `@std/id` because validation functions are commonly used together in form/API code. Clear separation: `@std/id` generates, `@std/valid` validates.

- **Removal over deprecation for redundant functions**: The 27 functions being removed from `@std/valid` are trivially replaceable with native Parsley features or schema constraints. No deprecation period needed since v1.0 is a breaking change boundary.

- **Deprecation aliases for moves**: Moved modules (`@std/api`, `@std/dev`, `@std/html`) get deprecation aliases that emit warnings but still work, easing migration.

- **Hash module is for checksums**: `@std/hash` is explicitly for checksums, cache keys, ETags, and non-security hashing. Password hashing uses Basil's auth system.

### Edge Cases & Constraints

1. **NanoID length validation** — `valid.nanoid(str, len?)` must accept optional length parameter (default 21). Validates character set `[0-9A-Za-z_-]` and length.

2. **Case conversion edge cases** — Must handle:
   - Already-converted strings (`"helloWorld".toCamel()` → `"helloWorld"`)
   - Mixed delimiters (`"hello_world-test".toCamel()` → `"helloWorldTest"`)
   - Acronyms (`"XMLParser".toSnake()` → `"xml_parser"`)

3. **Truncation with Unicode** — `truncate()` should count Unicode graphemes, not bytes.

4. **Base64 decode errors** — `fromBase64()` returns error for invalid Base64 input.

5. **Deprecation alias loading** — Old imports must still work (with warning) to avoid breaking existing code during transition.

### Validation Patterns

| ID Type | Regex |
|---------|-------|
| ULID | `^[0-9A-HJKMNP-TV-Z]{26}$` (Crockford Base32) |
| UUID | `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$` |
| NanoID | `^[0-9A-Za-z_-]+$` with length check |
| CUID2 | `^c[0-9a-z]{24}$` |

**String validators (5):** `matches`, `alpha`, `alphanumeric`, `numeric`, `empty`

## Implementation Notes

Implementation completed 2025-02-26.

### Key Implementation Details

1. **@std/schema deprecation**: Changed from hard error to warning (DEP-002) to avoid breaking existing tests that use schema-table binding. The functionality still works but users are directed to `@schema` DSL.

2. **@std/valid refactor**: Kept `luhnCheckGeneric()` separate from `luhnCheck()` (credit card specific) to allow generic Luhn validation without length constraints.

3. **String case conversion**: Created `splitIntoWords()` helper that handles snake_case, kebab-case, camelCase, and PascalCase inputs uniformly.

4. **Namespace moves**: Used deprecation warnings (not errors) for `@std/api`, `@std/dev`, `@std/html` to allow gradual migration. All three are now also available at `@basil/api`, `@basil/log`, `@basil/html`.

5. **Module metadata**: Added `htmlModuleMeta` for help system support; registered `hash`, `api`, `log`, `html` in appropriate metadata maps.
